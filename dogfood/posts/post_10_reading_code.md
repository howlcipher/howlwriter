# Software Maintenance: Why Reading Code is 80% of the Job

Most computer science programs and coding bootcamps teach programming as an act of creation: start with an empty editor, write new functions, and run the program.

In professional software engineering, starting from an empty file is an extreme rarity. More than 80% of an engineer's time is spent reading existing code: tracing execution paths through legacy services, reading git blame annotations, understanding why a quirky conditional was added three years ago, and checking edge cases before modifying a shared library.

Writing code is relatively easy; reading and understanding code written by someone else under tight deadlines is the true skill. If your code is not optimized for human readability, you are creating technical debt for every engineer who touches it after you.
