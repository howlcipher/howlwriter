## Unreleased

* Align discussion and peer-reply review on the same body text and assignment count. Report evaluation sample sizes separately and keep reference entries available for citation checks.
* Extract and validate model refinement envelopes before writing. Preserve the returned Markdown and keep the source text when the provider reports a no-op.
* Check direct-address step and question attributions against the supplied peer text. Require a substantive attribution for a grounded reply.
* Hold academic drafts for review when an explicit live observation lacks matching live evidence or a Windows event identifier is unsupported, including identifiers in lists. Carry fixture and predicate scope into drafting instructions.
* Resolve same-author, same-year and undated APA citation labels consistently during drafting and reference generation. Format standalone work titles and reference paragraphs for Word and both PDF renderers. Document the public local academic workflow and launcher recovery.

* Make the test suite hermetic and tighten the lint gate. Every test now runs with its own empty home folder, HowlWriter stores (voices, identities, projects, credentials, preferences), XDG folders and git identity, so a run no longer creates or reads `~/.howlwriter` or the developer's git settings. HowlWriter no longer imports the legacy `src.control_plane` layout: HowlPlane is found as `howlplane.control_plane`, from an installed package or from a checkout that has `src/howlplane` or `howlplane` (a folder without that package is never added to the import path). CI lint now covers `tests/` and checks F811, F841, F632 and F541 in addition to F821 and F401; the unused imports and variables it found were removed.
* Fix publishing and verification: `google logout` reports what it actually did; Drive folder IDs are validated and quoted in queries; entailment checks notice negation; repository evidence requires explicit roots, stays inside them and checks cited commits; DOI lookups validate the identifier before contacting a service.
* Harden the web server: requests are accepted only for the hosts being served; cross-origin write requests are refused; static files are served only from the bundled folder; document endpoints and publishing accept only text files in ordinary folders; CORS headers are removed; `howlwriter ui` refuses non-loopback hosts unless `--allow-network-access` is given. FastAPI 0.132 or newer is required.
* Make storage and the web runtime safer under concurrency: writes are atomic with unique temp files, and private files are fsynced and created with mode 0600; identity, workshop and project records are locked; web handlers no longer block the event loop; server-sent events are thread safe.
* Fix model locality checks: an unknown provider counts as remote and needs the remote yes; Ollama cloud tags also need the remote yes; `governed_run` no longer uses `preexec_fn`; TShark staging works inside Flatpak.
* Make command results consistent: `paper` exits 3 when the paper is not READY; `linkedin` not-ready results exit 3 and `--json` uses the `howl.result/v1` envelope; LinkedIn publisher recovery covers earlier days; the interop environment variable list is complete.
* Update CI: actions are pinned to release commits, Python 3.14 is tested, a release-notes check is added, and stale files were removed.
* Add the LinkedIn human approval boundary (milestone M3 of `docs/linkedin-publisher/ROADMAP.md`, built and tested locally, not yet run on GitHub): new `howlwriter linkedin review`, `approve` and `authorize-schedule` commands and module `howlwriter.linkedin.approval`. `approve` works only inside a first attempt manual dispatch of the approval workflow whose GitHub actor ID equals the configured trusted ID, and only when the approver passes the content fingerprint and limitations digest that `review` showed. Approval and schedule authorization records are authenticated with HMAC-SHA256 using a key held outside the repository; forged, altered, moved, expired or out of schedule approvals are refused by the new publish gate. New setting `approval_max_age_days` (default 30). A verification refresh that adds limitations the approver never accepted now returns the post to draft. A workflow template is in `docs/linkedin-publisher/workflows/`. Fixes from the pre-merge review: local `reschedule` and `reschedule-all` refuse to move an approved post (it used to be left unpublishable); only the newest schedule authorization counts, so a superseded slot cannot be replayed; linked approval records are refused; a dry run evaluates the gates and reports BLOCKED when a real run would block; recovery repairs a ledger entry left at INTENT after the post was closed; `verify` refuses to attach or withdraw when the post changed while HowlProof ran.
* Add LinkedIn post verification (milestone M2 of `docs/linkedin-publisher/ROADMAP.md`): `howlwriter linkedin verify` builds a package from a post, runs the real HowlProof program on it with an operator owned contract (`howlproof.post.yaml`, written once by `linkedin init`), adds deterministic checks HowlProof has no evaluator for (formatting, broken Unicode, link consistency, duplicates, privacy patterns, image container and alt text, figures not covered by a declared claim), and stores a report under `verification/`. The report verdict is HowlProof's own and is null when HowlProof gives no usable result; a post is eligible for human approval or blocked, never approved. Links are contacted only with `--allow-network`, through `howlproof acquire`. A stored report is rechecked against its hash, the sealed HowlProof bundle and the current media and evidence before it is accepted, and a report older than the new `verification_max_age_days` setting (default 7) blocks publication. HowlProof is not a dependency: without it `verify` blocks.
* Add the LinkedIn publisher foundation (milestones M0 and M1 of `docs/linkedin-publisher/ROADMAP.md`): package `howlwriter.linkedin` with a versioned post schema and strict parser, a content fingerprint that binds approval to exact text, links and media, an explicit lifecycle, validated `publisher.yaml` configuration, a timezone and daylight saving aware scheduler, atomic compare and swap persistence, a persistent one post per day ledger, and a publish protocol that saves intent before sending and never retries an unclear result. New command group `howlwriter linkedin` (init, add, edit, list, show, validate, submit, schedule, cancel, queue, evaluate, reschedule, reschedule-all, pause, resume, archive, reconcile). Nothing can be approved or sent yet: verification, human approval and the LinkedIn transport are later milestones and the defaults refuse. `jsonschema` joins the `dev` extra for schema contract tests.
* Fix PDF fallback data loss after column 80 by using ReportLab Platypus wrapping and pagination. Preserve headings, tables, captions, local figures, explicit page breaks, and page numbers. Include ReportLab in the PDF extra and report fallback failures.
* Embed local Markdown figures and explicit page breaks in DOCX and Chromium PDF output. Close Chromium on rendering errors. Add regression coverage for long prose/code, tables, captions, figures, page breaks, and missing-image failures.
* Preserve fenced command lines in DOCX without Markdown fragments. Keep fallback PDF title-page metadata in the body font and avoid single-line paragraph widows/orphans.

## 0.1.1

* `citations verify` compares each source's authors, year, edition, title, DOI and identifier with canonical records (publisher records outrank registry records) and reports `VERIFIED`, `MISMATCH`, `INCOMPLETE`, `UNVERIFIABLE` or `NEEDS_REVIEW`; a provider outage is never a wrong citation, a year the records disagree about needs the publisher's own cite-as year, and verified metadata is never claim support. `paper --verify-sources --records` applies it to the cited sources.
* Citations are re-checked after editing: dropped, added or changed citations and orphaned or missing references hold a `paper` for review.
* `lint --workflow-leakage` and the `paper` pipeline report workflow commentary that leaked into prose (for example "this is my recommendation, not a cited result"); legitimate qualifications are kept.
* Academic genres `academic_discussion`, `academic_peer_reply` and `academic_research_paper` use the existing academic voice profile. `evaluate --mode academic_*` previously fell through to an unknown context; it now routes to the academic profile.
* `reply check` and `paper --peer-post` ground a reply in the post it answers and treat posts and retrieved text as untrusted reference data (fenced in prompts, scanned for embedded instructions).
* `assignment check` evaluates a multi-document package and reports `BLOCKED`, `INCOMPLETE`, `NEEDS_REVISION`, `VERIFICATION_UNAVAILABLE` or `READY_FOR_HUMAN_REVIEW`, with a record of each check, its component, evidence and limits, and one-work-one-metadata consistency across documents.
* `finalize --changes` accounts for each change between a document and its revision.
* The Google Docs publisher confirms by read-back, writes updates only against the revision it read, refuses content that differs from the approved hash, records the approved artifact, and no longer asks the Docs API to delete a document's final newline. Results are `SUCCESS`, `UNCONFIRMED`, `CONFLICT` or `FAILED`.
* Independent audits of this work found and closed: a wrong year passing when the publisher record states none, given-name and edition-ordinal comparisons that were missing, a wrong DOI printed in every reference list, a deleted reference section reported as no change, an approval-hash check that failed open, a read-back that could not see reordered, short or appended content, quadratic regexes reachable from hostile text, and prompt metadata outside the fence. `assignment check` no longer returns ready when a required voice score or a citation check could not run.
* The `paper` report gains `workflow_leakage_findings`, `genre_findings`, `citation_changes_after_edit`, `citation_metadata_status`, `reply_grounding` and `sources_with_instruction_like_text`.

* Pin the `plane` extra and the real integration CI checkout to reviewed HowlPlane `4ba3e71`, including malformed-state exit and published Frame artifact compatibility corrections. The CI checkout previously followed moving `main` despite being labeled pinned; it now tests the same immutable revision the extra installs.

* Pin shared howl-provider-core `9bf1f78`, matching HowlDream and HowlCreate, restoring historical credential coverage and sanitizing provider failure metadata before persistence (Mission 007 F2).
* Invalid `runs prune` retention arguments now exit 1, including conflicting flags, negative settings, and overflowing day counts; synthetic regression tests verify no run artifacts change (F10).
* Keep portability-test environment isolation intact while testing unavailable and unconfigured HowlPlane.

* `howlwriter interop --json` prints the `howl.interop/v1` descriptor from the Howl interop contract: every command and flag (from the live parser), the documents `native request|write` produce, and the exit codes. HowlPlane and `howl doctor` use it to check the commands they run.
* A model chosen with `--provider` (or `HOWLWRITER_PROVIDER`, or the page) when HowlPlane cannot be imported now fails with exit 1 and names the missing package (web: HTTP 503 `howlplane_unavailable`). Before, it reported "needs a model" with exit 2, and steps with a rule-based path silently ran that path instead of the chosen model.
* A usage error (unknown flag or subcommand) exits 1 instead of argparse's 2, so 2 means only "a model step had no model chosen" (or the remote gate) and a caller such as HowlPlane cannot mistake an unsupported flag for a request for input.
* `HOWLPLANE_HOME` and `HOWLPLANE_DIR`, HowlPlane's own names for its checkout, are a fallback when `HOWLPLANE_ROOT` is unset and no installed HowlPlane can be imported; they never shadow an installed HowlPlane. New optional extra `howlwriter[plane]` installs HowlPlane for a plain pip install.

* Lines read from a data file (CSV, logs, JSON) are `directly_observed` only while the file is classified as experimental evidence; in any other category they are `extracted_from_source`, and the status follows a category change (the next scan updates an existing project). A parsed rating table or a reference's figures no longer read as the user's own measurements. Both statuses still count as fact.
* `project classify` and the category API record who set the category: `user` at a terminal or in HowlWriter's page, `owner_relayed` with `--owner-confirmed` (or `X-HowlWriter-Owner-Confirmed: 1`), and `agent` otherwise, instead of `user` for everyone. Each survives rescans as before.
* Document that a derived data table (ratings, a findings ledger) in `evidence/` must be classified as a draft or reference to stop counting as direct observation; the classifier goes by format and folder and cannot tell.
* Name the real cause when HowlPlane is found but cannot be imported (for instance a dependency of its own is missing in the Python HowlWriter runs in): model steps and the model menu now report the failed import and the Python path instead of "not configured" or "not installed".
* Read requirements from wrapped text, such as slide or column extraction, as whole sentences: wrapped lines are rejoined, a lead-in such as "You must include:" keeps the list after it (or gives way to its bullets), and "Please choose ..." and "you will create ..." instructions are found. Requirement IDs come from their text, so a rescan of such a project gives the changed rows new IDs and drops a status set by hand on the old ones; set those again.
* Keep the draft when a writer reply's YAML does not parse. A small model often indents only the first line under `body_markdown: |`; the whole reply (fence, keys and claim lists) then became the draft. The writer, outline writer, length correction and project draft now recover the body, and the claim lists when they parse.
* `writer` without `--sources` no longer asks the model for APA citations, which led small models to invent authors, years and figures; it asks for none. It also warns on stderr about any in-text citation that matches no supplied source and any exact identifier (such as a CVE) found in neither the sources nor the prompt, and `writer --fail-if-blocked` exits 3 on either.
* Add `project draft --fail-if-blocked`, which exits 3 when the draft's own validation verdict is not ready. Without it the exit code is unchanged (0, with the verdict in the output).
* Discover explicitly selected HowlPlane source checkouts using the current src/howlplane/control_plane layout while preserving installed packages and the legacy source layout.
* Show concrete environment binding and source checkout instructions in writer help and model role configuration errors.
* Correct onboarding documentation to reflect the existing environment based default role registry rather than claiming automatic configuration file loading.
* Add isolated process regressions for current, legacy, and installed discovery, absent packages, missing bindings, and public writer help. Discovery never executes a provider.
* Use SPDX MIT license metadata and a compatible setuptools floor so fresh wheel builds avoid deprecated license table warnings.
* Declare httpx2 as a development dependency for the current Starlette TestClient, avoiding its deprecated httpx fallback in fresh native test environments.
